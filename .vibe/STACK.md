### Frontend

_Primary UI layer._

- [**→ primary**] [React](https://github.com/facebook/react) (⭐ 247,256, MIT) — UI library; pair with Next.js, Vite or Astro.
- [alternative] [Next.js](https://github.com/vercel/next.js) (⭐ 141,789, MIT) — Default choice for React fullstack apps; App Router + server actions.
- [alternative] [Tailwind CSS](https://github.com/tailwindlabs/tailwindcss) (⭐ 97,250, MIT) — Utility-first CSS; strong AI-codegen affinity.

### Backend

_Skip if the frontend framework already covers server logic (e.g., Next.js server actions)._

- [**→ primary**] [NestJS](https://github.com/nestjs/nest) (⭐ 76,373, MIT) — Structured, opinionated framework for larger teams.
- [alternative] [Express](https://github.com/expressjs/express) (⭐ 69,362, MIT) — Most-known Node HTTP framework; huge ecosystem.
- [alternative] [Fastify](https://github.com/fastify/fastify) (⭐ 36,989, MIT) — High-performance alternative to Express with schema validation built in.

### Database

_Persistence layer; always use versioned migrations._

- [**→ primary**] [Supabase](https://github.com/supabase/supabase) (⭐ 107,981, Apache-2.0) — Postgres + Auth + Storage; enable RLS on every table.
- [alternative] [Prisma](https://github.com/prisma/prisma) (⭐ 47,575, Apache-2.0) — Typed ORM with versioned migrations.
- [alternative] [Drizzle ORM](https://github.com/drizzle-team/drizzle-orm) (⭐ 35,477, Apache-2.0) — SQL-first lightweight ORM; great edge/serverless fit.

### Validation

_Schema validation is mandatory on every external input (Constitution Law 3)._

- [alternative] [Yup](https://github.com/jquense/yup) (⭐ 23,674, MIT) — Mature option, common in form ecosystems.
- [alternative] [Valibot](https://github.com/fabian-hiller/valibot) (⭐ 8,929, MIT) — Smaller bundle alternative to Zod.

### Testing
