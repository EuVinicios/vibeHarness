# Product Requirements Document — @vibeharness/cli
> Originally generated by vibe-harness on 2026-08-14; filled with real content during the v0.5.1 dogfooding cycle.

## 1. Problem Statement

AI-assisted development ("vibecoding") produces code fast but unaccountably: secrets get committed, compliance (LGPD) is ignored, stacks are chosen by hype, and there is no readiness gate before shipping. Developers — especially non-senior ones — need a single tool that turns vibecoding into secure, auditable engineering instead of piecing together gitleaks, lint rules, checklists and PR templates by hand.

## 2. Target Users / Personas

- **Primary — the "vibecoder":** a solo dev or small-team dev building SaaS/landing/API projects with Cursor, Claude Code, Copilot or Windsurf. Ships fast, knows the tools, but lacks a security/compliance checklist and often doesn't know what they don't know. Wants guardrails without reading OWASP.
- **Secondary — tech lead of a small team:** wants an enforced Definition of Done (audit score ≥ N in CI) and consistent project scaffolding across the team.
- **Tertiary — agency/freelancer in Brazil:** must deliver LGPD-compliant projects to clients; needs the DSR/consent/PII checks baked into the workflow.

## 4. Core Features (MVP)

- [x] `start` — guided entry point (one question, stage detection, runs the lifecycle)
- [x] `prd` / `init` / `plan --apply` — spec-driven foundation with curated registry
- [x] `pack` — sanitised context (secrets redacted, key material excluded)
- [x] `audit` — 7-section scorecard (security, CVEs, LGPD, dead code, DB, infra, a11y) + AUDIT_REPORT.md with injection-safe AI fix prompts
- [x] `doctor` — EOL runtimes, outdated deps, lockfile, Dependabot generation, GitHub posture via `gh`
- [x] AI skill layer (Claude Code skill + slash commands, AGENTS.md, Cursor/Windsurf/Copilot rules)

## 5. Success Metrics

- [x] Dogfooding: VibeHarness scores **100/100 (Grade A)** on its own repository (achieved 2026-08-14, v0.5.1)
- [ ] npm weekly downloads ≥ 500 within 3 months of the 1.0 release
- [ ] ≥ 30% of `init` users reach `audit` in the same project (lifecycle completion)
- [ ] CI gate adopted: ≥ 100 repos running the audit in GitHub Actions
- [x] Zero false-positive redactions in the self-`pack` (achieved v0.5.1 — was 5)

## 6. Out of Scope (MVP)

- No cloud service / telemetry — the CLI is 100% local; the registry is a shipped snapshot
- No automatic fixing of findings (the AI fix prompts are executed by the user's AI, not by us)
- No SAST engine of our own — we integrate/recommend (gitleaks, osv-scanner, CodeQL) instead of reimplementing
- No support for non-JS stacks in `plan --apply` recipes (Python/Go stay recommendation-only for now)
- No marketplace for community rules/recipes

## 7. Non-Functional Requirements

- **Security:** no known High/Critical vulnerabilities at release (`npx @vibeharness/cli audit` = 100/100); all CI actions pinned by commit SHA; npm provenance on publish.
- **Privacy:** the CLI processes no user data beyond the local filesystem; `pack` redaction is best-effort and documented as such.
- **Performance:** full `audit` on a mid-size repo completes in ≤ 10 s (local, parallel scanners).
- **Reliability:** `npm test` ≥ 100 tests green on every PR; `--fail-under` gates enforced in CI.
- **Accessibility:** generated visual report (`audit --site`) uses system fonts, dark-mode support and copy buttons with focus states.

## 9. Definition of Done

A feature is "done" when:
1. All acceptance criteria are met.
2. Unit and integration tests pass (`npm test`).
3. `npx @vibeharness/cli audit` score ≥ 70 (this repo's own gate: ≥ 97, currently 100).
4. Code review approved (PR-only workflow, protected `main`).
5. No open security findings from `npx @vibeharness/cli audit`.
6. Lint (`npm run lint`) and dead-code (`npm run knip`) checks clean.
