# Product Requirements Document — @vibeharness/cli
> Generated by vibe-harness on 2026-08-15.
> This is a living document — keep it updated as the product evolves.

## 1. Problem Statement

Vibecoders (developers with low technical setup knowledge who build via AI clients) cannot drive the vibe-harness lifecycle. The current interface — an interactive terminal cockpit (`start`, v0.6.0) — forces them to alternate between terminal and AI client, copy prompts via clipboard, and understand 8 subcommands. The tooling they already use (Jest, gitleaks) succeeds because it is trivially installed and runs *with* the AI, not beside it. VibeHarness has all the engines (PRD, plan/apply, pack, audit, doctor) but no abstraction that lets the AI client itself orchestrate them.

## 2. Target Users / Personas

**Primary — the vibecoder:** builds apps by chatting with Cursor / Claude Code / Windsurf / Copilot / opencode / Antigravity / Qwen. Can run one `npx` command, but does not know what a lifecycle is, what order to run things, or how to interpret audit findings. Lives inside the AI client; the terminal is a foreign land.

**Secondary — the AI agent itself:** Claude Code, Cursor agents, opencode, etc. Needs deterministic, headless access to the harness (MCP tools + `--json`) so it can run the lifecycle autonomously and fix its own findings.

## 3. User Stories

| # | User Story | Priority | Status |
|---|------------|----------|--------|
| 1 | As a vibecoder, I want to install everything with ONE command (`vibe-harness install`) targeting my AI client, so that rules + MCP + skills are wired without manual steps | P0 | ⬜ |
| 2 | As a vibecoder, I want to just chat ("quero um SaaS de agendamentos") and have the AI run the whole harness (PRD → plan → pack → audit → fix) by itself, so that I never memorise commands | P0 | ⬜ |
| 3 | As an AI agent, I want MCP tools (`vibe_status`, `vibe_prd`, …) returning structured JSON, so that I can orchestrate the lifecycle and fix findings without parsing terminal cosmetics | P0 | ⬜ |
| 4 | As an AI agent, when a questionnaire is unanswered I want the tool to return `pendingQuestions[]`, so that I ask the human in chat instead of blocking on terminal prompts | P0 | ⬜ |
| 5 | As a vibecoder, I want a non-interactive `vibe-harness` status panel that tells me where the project stands and what to ask my AI next, so that the terminal is optional | P1 | ⬜ |
| 6 | As an AI agent, after `plan --apply` I want wiring instructions for the generated starters, so that I can integrate them into the app (with user consent) and close the loop | P1 | ⬜ |
| 7 | As a vibecoder on any of 7+ AI clients (Claude Code, Cursor, opencode, VS Code Copilot, Windsurf, Antigravity, Qwen), I want my client to be supported, so that adding a client is data (registry entry), not code | P1 | ⬜ |

## 4. Core Features (MVP)

- [ ] `vibe-harness install [client]` — one-command setup: AI rules, MCP server registration, skills/slash commands for the detected/chosen client; adapters declarative in `registry/clients.json`
- [ ] `vibe-harness mcp` — stdio MCP server exposing tools: `vibe_status`, `vibe_init`, `vibe_prd`, `vibe_plan` (apply), `vibe_pack`, `vibe_audit` (findings + sanitized fix prompts), `vibe_doctor`
- [ ] Headless core: all lifecycle logic extracted to pure actions (`src/actions/*`) returning `ActionResult` (data + `pendingQuestions[]` + `nextStep` + `outputs`), zero I/O cosmetics
- [ ] `--json` flag on every CLI command (deterministic output for agents and CI)
- [ ] `vibe-harness` default command becomes a non-interactive `status` panel (score, stage, next step, ready-to-paste AI prompt); Conductor cockpit retired
- [ ] `plan --apply` returns `wiringInstructions[]` per starter; status shows an integration checklist until starters are wired
- [ ] Unify file-write policy (init skip-existing vs rules overwrite) behind one explicit `--force` semantic

## 5. Success Metrics

- [ ] Time from `npx @vibeharness/cli install` to "AI can run the lifecycle" ≤ 1 minute, zero manual file edits
- [ ] A vibecoder with no CLI knowledge completes idea → audit ≥ 70 purely by chatting (agent-driven)
- [ ] MCP server works in Claude Code + Cursor + opencode (three live clients verified)
- [ ] Adding a new AI client requires only a `registry/clients.json` entry (no src/ change)
- [ ] `audit` score of this repo ≥ 70, no critical findings, all tests green

## 6. Out of Scope (MVP)

- [ ] Remote/hosted MCP (HTTP transport) — stdio only for now
- [ ] Auto-editing the user's `src/` code (wiring starters remains AI-assisted with consent, never direct CLI writes)
- [ ] GUI/web dashboard (the HTML audit report stays)
- [ ] Windows-specific installers for security binaries beyond existing Homebrew path
- [ ] Translating command banners to pt-BR (docs remain PT-BR; CLI stays EN)

## 7. Non-Functional Requirements

- **Security:** no known High/Critical vulnerabilities at release (`npx @vibeharness/cli audit`). MCP tool output sanitized with the same anti-prompt-injection pipeline as AUDIT_REPORT.md.
- **Privacy:** no telemetry, no network calls at runtime (MCP runs local stdio; registry is a shipped snapshot).
- **Performance:** MCP tool responses return in ≤ 2s p95 (audit tool uses the existing score cache when fresh).
- **Compatibility:** Node ≥ 18; zero new runtime deps beyond `@modelcontextprotocol/sdk`.

## 9. Definition of Done

A feature is "done" when:
1. All acceptance criteria are met.
2. Unit and integration tests pass.
3. `npx @vibeharness/cli audit` score ≥ 70.
4. Code review approved.
5. No open security findings from `npx @vibeharness/cli audit`.
